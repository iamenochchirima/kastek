## Route/process entry format

Add detailed entries during phase 0 in this file or a linked manifest next to it. Use one row per registered operation or process command, with these fields:

`ID | owner | method/path or process mode | Rust source | caller | auth/scope | inputs/outputs/errors/transports | database/effects | TS destination | verification evidence | status | retirement commit`

Document conditional routes and disabled/unavailable providers. If code or a live check is blocked, state the concrete reason and the required next action. A source review or a typecheck does not establish runtime parity.
